# Prop Copy Trading Bot (UpScale)

## Цель проекта

Telegram-бот для оказания услуг копитрейдинга на проп-фирме UpScale. Владелец (и назначенные им админы) добавляют трейдеров, дающих сигналы, и подписчиков. Бот отслеживает позиции трейдера через API UpScale и автоматически открывает пропорциональные копии позиций на счетах подписчиков. Сервис позволяет любому участнику торговать одновременно на нескольких счетах, открывая позиции только на одном.

## Интерфейс

- Единственный интерфейс — Telegram-бот: меню, inline-кнопки, текстовые экраны, уведомления.
- Роли: **владелец** (Telegram ID 5177702263), **админ** (назначается владельцем), **трейдер-сигнальщик** (назначается владельцем/админом), **участник** (подписчик, добавляется вручную).
- Токен Telegram-бота передаётся владельцем через защищённую форму и хранится только в окружении сервера.
- Получение обновлений: webhook (`app/api/telegram/webhook`) либо long polling без публичного HTTPS-адреса — скрипт `npm run bot:polling` (`scripts/telegram-polling.ts`), оба используют общий обработчик `lib/telegram/handler.ts`; скрипт проверяет токен через `getMe`, снимает webhook и печатает понятный отчёт, если окружение не имеет доступа к `api.telegram.org`.

## Интеграция с UpScale API (по официальной документации)

- Базовый URL: `https://api.upscale.trade`; аутентификация — персональный API-ключ `usk_...` в заголовке `Authorization: Bearer`.
- API-торговля включается отдельно для каждого счета (`apiTrading`); списки счетов с ключом включают только счета с включённой API-торговлей.
- Все числа — необработанные строки fp9 (значение × 10⁹); чтение и запись только через BigInt/Decimal.
- Ключевые эндпоинты:
  - `GET /accounts/with-risk-status` — все счета ключа с фазой, статусом, балансом, эквити, лимитами просадки фазы, `apiTrading`;
  - `GET /accounts/risk-status`, `GET /accounts/{accountId}/risk-status` — снимки риска: `dayStartEquity` (база дневной просадки), `currentEquity`, `maxEquity` (база трейлинг-просадки);
  - `GET /accounts/{accountId}/equity-history` — эквити по минутам;
  - `GET /accounts/{accountId}/stats` — агрегированная статистика закрытых позиций: винрейт, средний RR (`riskRewardRatio`), среднее/медианное время удержания, число позиций, топ-актив;
  - `GET /v2/markets?accountId=…` и `GET /v2/markets/{id}` — рынки с id, ценой, комиссиями, границами плеча;
  - `POST /orders` — ордера: `market` открывает позицию (`amount` — резерв в USD из свободного баланса, `leverage`, опционально `stopTriggerPrice`/`takeTriggerPrice`); закрытие — ордер `take` с `triggerPrice: "0"` и `amount` = размер позиции в базовом активе; `x-idempotency-key` обязателен для безопасных повторов записи;
  - `GET /positions/{accountId}/active` — открытые позиции (ответ ордера не содержит id позиции, её находят чтением позиций); полная история: `GET /positions/{accountId}/portfolio/history`; события позиции: `GET /positions/{positionId}/history` (ревизия `version` растёт при каждом событии);
  - `PATCH /orders/{orderId}` — редактирование ожидающего ордера (замена ордера, новый id); `DELETE /orders/{orderId}` — отмена;
  - `PATCH /positions/{positionId}/margin` — изменение маржи позиции;
  - `POST /positions/{accountId}/close-all`, `POST /accounts/{accountId}/close-all` — закрытие всех позиций (и всех позиций+ордеров) по рынку;
  - `GET /positions/{accountId}/{asset}/open-notional` — открытый номинал по направлению перед увеличением позиции.
- Лимиты запросов на ключ: 10 запросов/сек и 60/мин отдельно на чтение и запись; 429 с `Retry-After` — бот обязан уважать и не превышать лимиты.
- Ошибки возвращаются со стабильным машинным кодом (`error`); бот ветвится по коду (`insufficient_balance`, `api_trading_not_enabled`, `market_paused` и т.д.) и информирует пользователя понятным сообщением.

## Основные возможности

### 1. Управление доступом (подписки вручную)

- **Цель:** владелец полностью контролирует, кто пользуется сервисом.
- **Описание:** владелец (и назначенные им админы) добавляет пользователя вручную по Telegram ID, задаёт ему тег (отображаемое имя) и выбирает срок доступа в днях. По истечении срока доступ автоматически прекращается, бот сообщает пользователю и предлагает связаться с админом. Админы назначаются только владельцем. Трейдером, дающим сигналы, может быть назначен только добавленный пользователь — право назначать трейдеров есть только у владельца и его админов.
- **Критерии приёмки:**
  - Владелец добавляет пользователя по Telegram ID с тегом и сроком доступа в днях — пользователь получает доступ к боту.
  - Владелец назначает и снимает админов; админы могут добавлять пользователей, но не могут назначать трейдеров.
  - После истечения срока доступа бот перестаёт выполнять команды пользователя и уведомляет его об истечении подписки.
  - Пользователь без доступа не видит разделы бота и получает сообщение, что доступа нет.

### 2. Свои счета (привязка API UpScale)

- **Цель:** участник без затруднений торгует одновременно на нескольких счетах, открывая позиции только на одном.
- **Описание:** каждый участник в разделе «Мои счета» привязывает API-ключ своего основного счета (источник сделок) и одного или нескольких дополнительных счетов, на которых бот будет открывать копии позиций. Бот проверяет ключ через `GET /accounts/with-risk-status`, показывает найденные счета с балансом/эквити/фазой и помечает счета без включённой API-торговли. API-ключи хранятся защищённо и никогда не показываются в чате в открытом виде. Участник видит список своих счетов, какой из них основной, и может удалить/заменить привязку.
- **Критерии приёмки:**
  - Участник добавляет основной счет по API-ключу UpScale и видит его в списке как источник сделок.
  - Участник добавляет дополнительные счета и видит их в списке как счета для копирования.
  - По ключу отображаются счета UpScale с балансом, эквити, фазой и статусом API-торговли; счет с выключенной API-торговлей помечается как негодный для копирования.
  - API-ключи не отображаются в чате полностью (маскируются).
  - Участник может удалить привязанный счет, после чего бот перестаёт работать с ним.

### 3. Активные трейдеры сервиса

- **Цель:** участник осознанно выбирает, кого копировать.
- **Описание:** раздел со списком активных трейдеров сервиса. При нажатии на трейдера открывается его карточка: ник, количество сделок, на каких активах торговал, винрейт (успешность), средний RR, среднее время удержания сделки, сколько человек его копирует. Статистика берётся из `GET /accounts/{accountId}/stats` основного счета трейдера.
- **Критерии приёмки:**
  - Раздел показывает список активных трейдеров сервиса.
  - Карточка трейдера показывает ник, число сделок, активы, винрейт, средний RR, среднее время удержания и число копирующих.
  - Статистика обновляется после закрытия каждой сделки трейдера.

### 4. Подписка на трейдера и коэффициент копирования

- **Цель:** участник подключает автокопирование с нужным ему соотношением объёма.
- **Описание:** из карточки трейдера участник подписывается на него и выбирает соотношение копирования: 2:1, 1:1, 0,5:1 или произвольное. Соотношение определяет, во сколько раз объём копируемой позиции отличается от расчётной пропорции по размерам счетов. Участник может отписаться и сменить коэффициент.
- **Критерии приёмки:**
  - Участник подписывается на трейдера и выбирает коэффициент (2:1, 1:1, 0,5:1 или своё значение).
  - Участник видит список своих активных подписок с коэффициентами.
  - Участник может изменить коэффициент и отписаться; после отписки копирование прекращается.

### 5. Автоматическое копирование сделок

- **Цель:** позиции трейдера автоматически повторяются на счетах подписчиков в правильной пропорции.
- **Описание:** бот циклически опрашивает `GET /positions/{accountId}/active` по основному счету каждого трейдера и сопоставляет позиции с сохранённым состоянием. Новая позиция трейдера → бот вычисляет объём для каждого подписчика: пропорционально размеру счета подписчика к размеру счета трейдера, умноженному на выбранный коэффициент, и открывает `market`-ордер на дополнительных счетах подписчика через `POST /orders` с `x-idempotency-key`; id копии бот фиксирует по `GET /positions/{accountId}/active`. Увеличение позиции трейдера (рост size/version) → бот увеличивает копию. Закрытие позиции трейдера → бот закрывает копии ордером `take` с `triggerPrice: "0"` и `amount` = размер копии в базовом активе. Уведомления об открытии/закрытии копии отправляются подписчикам.
- **Пример из требований:** счет трейдера $10 000, позиция $5 000 (стоп-лосс −$100, тейк-профит $250); у подписчика счет $50 000 и коэффициент 1:1 — копия позиции в 5 раз больше. Стоп/тейк копируются пропорционально ценовым уровням исходной позиции.
- **Критерии приёмки:**
  - После открытия позиции у трейдера бот открывает копии на всех дополнительных счетах его подписчиков.
  - Объём копии равен объёму позиции трейдера × (счет подписчика / счет трейдера) × коэффициент подписки.
  - Стоп-лосс и тейк-профит копируются пропорционально ценовым уровням позиции трейдера.
  - Увеличение позиции трейдера отражается увеличением копий; копия закрывается, когда трейдер закрывает исходную позицию.
  - Подписчики получают уведомление об открытой и закрытой копии позиции.
  - Бот соблюдает лимиты запросов UpScale (10/сек, 60/мин на чтение и запись) и обрабатывает коды ошибок API понятными сообщениями.

### 6. Лимит дневной просадки

- **Цель:** защита счета участника от крупных дневных убытков.
- **Описание:** каждый участник задаёт свой дневной лимит просадки в процентах от счета. Бот отслеживает состояние счета по `GET /accounts/risk-status` (или `risk-status` отдельного счета): когда убыток от `dayStartEquity` достигает заданного процента, бот прекращает открывать новые копии позиций до конца дня и уведомляет участника. При срабатывании лимита бот может по желанию участника закрыть открытые копии (`POST /positions/{accountId}/close-all`). Лимит можно изменить в любой момент; на следующий день копирование возобновляется.
- **Критерии приёмки:**
  - Участник задаёт дневной лимит просадки в процентах.
  - При достижении лимита бот не открывает новые позиции до конца дня и уведомляет участника.
  - На следующий день лимит сбрасывается и копирование возобновляется.
  - Участник может изменить лимит в любой момент.

### 7. Статистика сделок

- **Цель:** каждая сделка учитывается в статистике трейдера и истории участника.
- **Описание:** после закрытия каждой копируемой позиции (успешной или убыточной) бот заносит сделку в статистику трейдера (число сделок, актив, результат, RR, время удержания) и в историю сделок участника.
- **Критерии приёмки:**
  - После закрытия сделки она появляется в карточке трейдера с результатом и активом.
  - Участник видит историю своих скопированных сделок с результатом.
  - Статистика учитывает и прибыльные, и убыточные сделки.

## Сценарии первой версии

- Владелец добавляет участника по Telegram ID с тегом и сроком доступа.
- Участник привязывает основной и дополнительные счета UpScale по API-ключам.
- Участник просматривает активных трейдеров, открывает карточку со статистикой и подписывается с коэффициентом.
- Трейдер открывает позицию — бот пропорционально копирует её подписчикам (включая стоп/тейк), увеличивает при увеличении и закрывает вместе с исходной.
- Бот останавливает копирование при достижении дневного лимита просадки и уведомляет участника.
- Участник и трейдер видят обновлённую статистику после каждой сделки.

## Дополнительные заметки

- Токен Telegram-бота и API-ключи UpScale — секреты: вводятся только через защищённые формы, хранятся в окружении сервера, никогда не попадают в код, чат, логи и документацию.
- Все числовые значения UpScale API — строки fp9 (×10⁹); расчёты объёмов копий ведутся в Decimal/BigInt без плавающей точки.
- Telegram ID владельца: 5177702263.
- Персистентное хранение — DynamoDB; данные (пользователи, счета, подписки, позиции-копии, сделки, лимиты, статистика) хранятся в базе, а не в файлах или памяти.
